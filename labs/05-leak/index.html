Lab 05 · The dialog that never leaves

Mission: Users who open and close the details dialog many times say the tab gets slower. Prove there's a leak, find what is leaking, and name the variable that keeps it alive.
Hint 1More tools → Performance monitor. Watch "DOM Nodes" while you click "Open + close × 20" several times.
Hint 2Memory → Heap snapshot. Click the 🧹 button, take a snapshot, click × 20 three times, click 🧹, take another. Switch to Comparison view, or filter the summary by "Detached".
Solution

Each dialog builds 500 rows, and closing it removes the dialog from the page. The same dialog element is also pushed into history, which is never cleared, so every closed dialog stays in memory as a detached DOM tree.

In the snapshot, filter by Detached, select a Detached HTMLDivElement, and read its Retainers: history → Array → element. To fix it, don't store DOM nodes; store only the data you need (e.g. an id).
